# Цели

## Текущие цели (подтверждаются кодовой базой)

1. **Детерминированное ядро симуляции** — тик с одновременным движением, разрешением взаимодействий, встречами и выплатами PD.
2. **Стабильный контракт движка** — FastAPI говорит только с `SimulationEngine`; бэкенд выбирается через `AGENTIKI_SIM_BACKEND`.
3. **Браузерная визуализация** — pan/zoom canvas, отрисовка агентов, debug-оверлей зрения/взаимодействия, импульсы контактов/PD.
4. **HTTP control plane** — просмотр мира/ячеек/агентов, step/reset, генерация популяции, запрос observation.
5. **Общий хеш ячеек** — Python и TypeScript используют один u32-алгоритм, чтобы клиентская сетка совпадала с seed симуляции.

## В области сейчас

* Бесконечное seed-поле 2D.
* Популяция агентов на сетке (generate / list / viewport query).
* Движение с разрешением конфликтов.
* Восприятие и взаимодействие в настраиваемых радиусах.
* Встречи + раунды Prisoner's Dilemma + score.
* Временная случайная стратегия для прогона механик.
* Запуск одной командой через Docker; локальная разработка в два процесса.

## Вне области сейчас

* Эволюционирующие геномы / отбор / размножение (**Fact:** поле `genome` у агента есть, но не используется).
* Незаглушенные биомы и влияние рельефа.
* Персистентное хранение / мультисессионные миры.
* Аутентифицированное мультипользовательское управление.
* Модуль симуляции на Rust (только заглушка в factory).
* Автоматические CI-пайплайны (**Fact:** в репозитории нет `.github` workflows).

## Практические критерии успеха

Разработчик может:

1. поднять стек (Docker или локально);
2. сгенерировать агентов и продвинуть мир;
3. видеть агентов, встречи и активность PD в UI;
4. запустить тесты: `uv run python -m unittest discover -s tests`;
5. найти, где менять конкретную механику (движение, взаимодействие, встреча, PD, восприятие), не читая всё дерево.
