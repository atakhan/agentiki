# Алгоритмы

## Хеш ячейки (общий Python / TypeScript)

Для целых `x`, `y`, `seed` (как unsigned 32-bit):

```text
h = seed
h = h + x * 0x9E3779B1
h = h XOR y
h = h + y * 0x85EBCA77
h = mix32(h)
```

`mix32` — фиксированный avalanche-mixer (`>>16`, умножение `0x7FEB352D`, `>>15`, умножение `0x846CA68B`, `>>16`), всегда с маской 32 бит.

Функции biome/color хеш игнорируют и возвращают константы.

## RNG тика

Seed RNG на тик:

```text
(seed XOR (tick * 0x9E3779B9)) AND 0xFFFFFFFF
```

Используется временной случайной стратегией (и любой стратегией, которая берёт RNG тика).

## Генерация популяции

1. Очистить прежнюю популяцию.
2. `spacing = clamp(round(density), 1, 10)` — расстояние в клетках до ближайшего соседа по оси. Это не вес и не радиус диска.
3. Поставить `count` агентов на квадратную решётку с шагом `spacing`, центрированную на origin. Столбцов — `ceil(sqrt(count))`, строк — `ceil(count / столбцов)`.
4. Id идут подряд с 1. Координаты зависят только от count, spacing и origin.

`PythonEngine.generate_agents` всё ещё считает

```text
seed XOR (generation * 0x9E3779B9) XOR (tick << 16)
```

и увеличивает счётчик генерации, но `AgentPopulation.generate` этот seed отбрасывает. На клетки он не влияет.

## Разрешение движения

Входы: карта занятости и для каждого агента `(from, to)`; bounds карты.

1. Цель вне `[0, W) × [0, H)` → трактовать как stay (`to = from`).
2. Для каждой цели с ходящими (`to ≠ from`) победитель = агент с наибольшим `move_priority(seed, tick, dest, agent_id)` (при равенстве — больший `agent_id`).
3. Для каждого агента успех рекурсивно:
   * stay → успех;
   * не победитель цели → провал;
   * цель пуста или это сам → успех;
   * жилец цели тоже целится в ту же клетку → провал;
   * иначе успех, если успешен ход жильца;
   * циклы зависимостей → провал.
4. Итог: `to` при успехе, иначе `from`.

`move_priority` — детерминированный u32-mix от `(seed, tick, dest_x, dest_y, agent_id)`. Это жеребьёвка, а не правило «меньший id всегда выигрывает».

## Еда: поиск, поедание, восполнение

1. **Видимость:** еда с Чебышёв ≤ `vision_radius` попадает в observation.
2. **Цель движения:** среди видимой еды выбрать минимальный Манхэттен; ничья — `rng.choice`. Один кардинальный шаг, уменьшающий Манхэттен.
3. **Eat:** среди видимой еды с Чебышёв ≤ `interaction_radius` выбрать ближайшую (тот же tie-break). `EatAction` → stay в движении.
4. **Потребление** (после `apply_positions`): для каждого `agent_id → food_id` проверить, что агент и еда ещё существуют и Чебышёв ≤ `interaction_radius`. Сгруппировать по еде; каждому едоку `+ food_energy / n` в `energy`; удалить порции.
5. **Восполнение:** на каждую удалённую порцию — клетка с минимальной плотностью агентов+еды в `food_density_radius`; ничья — max `move_priority(seed, tick, cell, 0)`. Новая еда того же вызова недоступна для поедания.

## Разрешение взаимодействий

Входы: карта initiator → target; множество занятых; популяция; радиусы; тик.

1. Отфильтровать валидные рёбра (радиус + существование + не busy), отсортировать по id инициатора.
2. Сначала взаимные: уникальные неупорядоченные пары, оба свободны → событие с двумя initiators.
3. Оставшиеся односторонние: событие с одним initiator; оба помечены used.
4. Отсортировать события по `(agent_a, agent_b)`.

## Выплаты PD

Выплата раунда прибавляется к **energy** обоим участникам один раз (отдельного score нет; жизнь не пополняется):

- оба сотрудничают — по +3 energy;
- оба предают — по +1 energy;
- один сотрудничает, другой предаёт — сотрудничающий +0, предающий +5.

Так начисляют и взаимная, и односторонняя встреча, если раунд сыгран. Несколько раундов суммируются. Energy не опускается ниже 0.

| A \ B | Cooperate | Defect |
| --- | --- | --- |
| Cooperate | (3, 3) | (0, 5) |
| Defect | (5, 0) | (1, 1) |

В коде: `reward=3`, `temptation=5`, `punishment=1`, `sucker=0`. Ограничение: `temptation > reward > punishment > sucker`.

Это значения по умолчанию. Их задают на экране конфигурации мира; «Старт» и «Рестарт» передают их в генерацию, каждый шаг сессии — в `POST /api/world/step`. Неверный порядок притока в конфиг не записывается.

## Пространственный запрос соседей (Чебышёв)

Опросить все spatial-корзины квадрата `[x±r] × [y±r]`, оставить сущности с расстоянием Чебышёва до ячейки наблюдателя `≤ r` (индекс популяции использует корзины размера 1, выровненные по клеткам).

## Жизнь (hp) и энергия (energy)

Отдельного score нет.

**hp** — срок жизни. При генерации `randint(start_hp_min, start_hp_max)` (дефолт 40…80). Каждый тик после действий/еды/PD: −`hp_tick` (дефолт 1). Не пополняется.

**energy** — ресурс действий. Старт `start_energy` (дефолт 100, задаётся в конфиге мира). При `energy ≤ 0` в конце тика — смерть. За тик, после движения:

- успешный переход: −`energy_move` (2)
- остался в клетке: −`energy_stay` (1)
- `InteractAction`: −`energy_play_decision` (1)

Затем поедание: `+ food_energy / n`.

На сыгранный раунд PD: `+payoff` → −`energy_game` → −`energy_play_decision` (continue/leave).

При `hp ≤ 0` или `energy ≤ 0` после трат тика агент удаляется.

## Оценка оппонента по генетическим шкалам

Ядро не входит в пайплайн тика. Полные правила, стоимость и границы генов — в [genetics](genetics.md). Кратко, история от старого эпизода к новому:

1. Окно — последние `shvgop` действий оппонента. `shvgop = 0` историю не читает. Короткая история берётся целиком.
2. Вес эпизода `a_i = shz^(N-i)`; у самого нового вес 1.
3. Вклад хода `w = x (1 + shpm · x)`, где `C = −1`, `D = +1`.
4. `S` — сумма `a_i · w_i`, не среднее.
5. `S > 0` → defect, `S < 0` → cooperate, `S = 0` → равновероятный выбор. Пустое окно вместо суммы использует знак `shpm` (ноль — та же монета).
6. Когнитивная стоимость равна длине окна. Из `energy` она не вычитается.
