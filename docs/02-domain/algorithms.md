# Алгоритмы

## Хеш ячейки (общий Python / TypeScript)

Для целых `x`, `y`, `seed` (как unsigned 32-bit):

```text
h = seed
h = h + x * 0x9E3779B1
h = h XOR y
h = h + y * 0x85EBCA77
h = mix32(h)
```

`mix32` — фиксированный avalanche-mixer (`>>16`, умножение `0x7FEB352D`, `>>15`, умножение `0x846CA68B`, `>>16`), всегда с маской 32 бит.

Функции biome/color хеш игнорируют и возвращают константы.

## RNG тика

Seed RNG на тик:

```text
(seed XOR (tick * 0x9E3779B9)) AND 0xFFFFFFFF
```

Используется временной случайной стратегией (и любой стратегией, которая берёт RNG тика).

## Генерация популяции

1. Очистить прежнюю популяцию.
2. `spacing = clamp(round(density), 1, 10)` — расстояние в клетках до ближайшего соседа по оси. Это не вес и не радиус диска.
3. Поставить `count` агентов на квадратную решётку с шагом `spacing`, центрированную на origin. Столбцов — `ceil(sqrt(count))`, строк — `ceil(count / столбцов)`.
4. Id идут подряд с 1. Координаты зависят только от count, spacing и origin.

`PythonEngine.generate_agents` всё ещё считает

```text
seed XOR (generation * 0x9E3779B9) XOR (tick << 16)
```

и увеличивает счётчик генерации, но `AgentPopulation.generate` этот seed отбрасывает. На клетки он не влияет.

## Разрешение движения

Входы: карта занятости и для каждого агента `(from, to)`.

1. Для каждой цели с ходящими (`to ≠ from`) победитель = `min(id претендентов)`.
2. Для каждого агента успех рекурсивно:
   * stay → успех;
   * не победитель цели → провал;
   * цель пуста или это сам → успех;
   * жилец цели тоже целится в ту же клетку → провал;
   * иначе успех, если успешен ход жильца;
   * циклы зависимостей → провал.
3. Итог: `to` при успехе, иначе `from`.

## Разрешение взаимодействий

Входы: карта initiator → target; множество занятых; популяция; радиусы; тик.

1. Отфильтровать валидные рёбра (радиус + существование + не busy), отсортировать по id инициатора.
2. Сначала взаимные: уникальные неупорядоченные пары, оба свободны → событие с двумя initiators.
3. Оставшиеся односторонние: событие с одним initiator; оба помечены used.
4. Отсортировать события по `(agent_a, agent_b)`.

## Выплаты PD

Отдельного score нет. Выплата раунда прибавляется к жизни (`hp`) обоим участникам один раз:

- оба сотрудничают — по +3 hp;
- оба предают — по +1 hp;
- один сотрудничает, другой предаёт — сотрудничающий получает +0 hp, предающий +5 hp.

Так начисляют и взаимная встреча, и односторонняя, если раунд реально сыгран. Решение взаимодействовать, которое не дошло до раунда, hp от выплаты не прибавляет. Несколько раундов одной встречи суммируются. Потолка у hp нет: выплата может поднять жизнь выше 60. Затраты не опускают hp ниже 0.

| A \ B | Cooperate | Defect |
| --- | --- | --- |
| Cooperate | (3, 3) | (0, 5) |
| Defect | (5, 0) | (1, 1) |

В коде: `reward=3`, `temptation=5`, `punishment=1`, `sucker=0`. Ограничение: `temptation > reward > punishment > sucker`.

Это значения по умолчанию. Их задают на экране конфигурации мира; «Старт» и «Рестарт» передают их в генерацию, каждый шаг сессии — в `POST /api/world/step`. На экране симуляции меню «Жизнь» нет. Неверный порядок притока (`предатель > оба C > оба D > кооператор` нарушен) в конфиг не записывается. Потолка hp нет, `spend_hp` не опускает hp ниже 0.

## Пространственный запрос соседей (Чебышёв)

Опросить все spatial-корзины квадрата `[x±r] × [y±r]`, оставить сущности с расстоянием Чебышёва до ячейки наблюдателя `≤ r` (индекс популяции использует корзины размера 1, выровненные по клеткам).

## Жизнь

Единственная валюта — hp. Отдельного поля score нет. На старте у агента 60 hp (`start_hp`).

За тик, после разрешения движения и до раундов:

- успешный переход в другую клетку: −2 (`hp_move`)
- остался в клетке: −1 (`hp_stay`) — stay, неудачный ход и участник встречи
- решение interact (`InteractAction`): −1 (`hp_play_decision`), даже если встреча не открылась

На каждый сыгранный раунд, в таком порядке:

- приток матрицы прибавляется к hp
- затем −1 за раунд (`hp_game`)
- затем −1 за выбор continue/leave (`hp_play_decision`)

При hp ≤ 0 в конце тика агент удаляется, встреча завершается. Приток того же раунда применяется раньше проверки смерти и может поднять hp выше 0 и выше стартовых 60.
