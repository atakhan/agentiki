# Обзор домена

Этот раздел описывает **предметную модель**: мир, агенты, время, восприятие, еда, контакт, встречи и выплаты — без привязки к классам Python/TypeScript.

## Мир

* **Конечная прямоугольная сетка** `[0, map_width) × [0, map_height)` (по умолчанию 64×64).
* Ячейка задаётся координатами `(x, y)`.
* При фиксированном **seed мира** у каждой ячейки есть детерминированная идентичность (хеш). Biome и цвет сейчас — однородные заглушки.
* Край жёсткий: ход за границу = stay.

## Время

* Время идёт дискретными **тиками** (`0, 1, 2, …`).
* **Step** продвигает один или несколько тиков.
* Внутри тика свободные агенты решают одновременно; затем контакты, движение, поедание еды и раунды встреч идут по фиксированному пайплайну (см. [mechanics](mechanics.md)).

## Агенты

* Агент занимает ровно одну ячейку.
* В ячейке не больше одного агента.
* У агента есть **hp** (жизнь): при генерации случайно в `[start_hp_min, start_hp_max]`; каждый тик −`hp_tick` (дефолт 1); **не пополняется**. При ≤ 0 — смерть.
* У агента есть **energy** (старт `start_energy`, дефолт 100): траты за действия, приток от еды и PD. При `energy ≤ 0` — смерть. Отдельного score нет.
* Агент либо **свободен**, либо **во встрече**.
* Может нести **геном** из трёх шкал (ШВГОП, ШПМ, ШЗ). Правила оценки — в [genetics](genetics.md). Тик и стратегия по умолчанию геном не читают и при спавне его не выдают.

## Еда

* На карте ровно `food_capacity` порций (по умолчанию 50); не больше одной на клетку; еда не блокирует ход.
* Агенты видят еду в `vision_radius` и идут к ближайшей (Манхэттен; шаги N/S/E/W).
* Поедание — отдельный тик (`EatAction`): еда уже в `interaction_radius`, агент стоит и ест. Подойти и съесть за один тик нельзя.
* Несколько едоков одной порции делят `food_energy` поровну → `agent.energy`. После удаления порция восполняется.

## Восприятие и действие

* Каждый свободный агент видит других агентов и еду в **радиусе зрения** (Чебышёв).
* По observation выбирает **движение**, **поедание** (`EatAction`) или **взаимодействие** с целью в **радиусе взаимодействия**.
* Радиус взаимодействия не может превышать радиус зрения.

## Контакт и встречи

* По умолчанию `enable_pd=False`: новые взаимодействия / встречи / раунды PD не стартуют; код сохранён.
* При `enable_pd=True`: валидные намерения взаимодействия превращаются в **события взаимодействия** (контакты).
* Новая встреча начинается только если на начало тика агенты — соседи по Чебышёву (`interaction_radius`, по умолчанию 1). Дистанция ≥ 2 встречу не открывает.
* Контакт может открыть **встречу** двух агентов. Дальше встреча не перепроверяет соседство. Пока встреча активна, участники не ходят, но могут есть.
* На встрече играются раунды **Prisoner's Dilemma**; после каждого раунда оба выбирают **продолжить** или **уйти**.
* Встреча заканчивается, если не оба продолжили, либо если участник умер (hp ≤ 0 в конце тика). Каждый сыгранный раунд меняет **energy**: сначала приток матрицы, затем стоимость раунда.

## Поверхность управления (доменный взгляд)

В UI оператор:

* на главной выбирает «Новый мир» или «Загрузить мир»;
* на экране конфигурации задаёт размер карты, число агентов, плотность `1…10`, правила еды и жизни, затем «Старт» или «Сохранить конфиги»;
* «Загрузить мир» открывает тот же экран уже заполненным, не симуляцию;
* на симуляции включает play/pause, «Рестарт» (тот же конфиг, камера на месте, пауза, тик 0), масштаб и «Вид», возвращается назад и смотрит инспектор агента (hp, energy, встреча, радиусы).

На экране симуляции нет меню числа агентов, плотности и «Жизнь». Ручных «Шаг» и «×10» нет. По HTTP по-прежнему доступны просмотр мира, генерация, step, reset, food и observation. Это операции управления, а не внутримировые действия агента.
