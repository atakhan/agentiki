# Генетические шкалы (v0.1)

Ядро оценки оппонента. Три гена задают, как агент читает прошлые ходы конкретного оппонента и какой ход PD выбирает. Эффективность комбинаций генов этой спецификацией не утверждается: её должны показать прогоны.

Тик, встречи и `RandomTestStrategy` это ядро **не вызывают**. Память эпизодов сама не заполняется. Мутации, наследование от двух родителей и стартовое распределение генов в v0.1 не заданы и в коде отсутствуют.

## Гены

| Ген | Поле | Диапазон | Смысл |
| --- | --- | --- | --- |
| ШВГОП | `shvgop` | целое `0 … 256` | Сколько последних эпизодов читать |
| ШПМ | `shpm` | вещественное `[-1, 1]` | Как взвешивать C и D; первый ход без истории |
| ШЗ | `shz` | вещественное `[0, 1]` | Насколько старые эпизоды ещё влияют |

`256` — принятая граница `N_max`: спецификация требует конечный диапазон и число не называет. Значение вне диапазона в `Genome` не создаётся. В течение жизни модуль гены не меняет.

Эпизод — действие **оппонента**: сотрудничество `C = −1`, дефекция `D = +1`. Свой ход в оценку не входит.

## Окно и стоимость

ШВГОП `N` берёт последние `N` эпизодов с этим оппонентом. История короче — берутся все имеющиеся. Порядок в окне: от старого к новому.

`N = 0` не читает память и не читает переданную историю. Стоимость тогда 0.

Когнитивная стоимость — число реально прочитанных эпизодов, `Cost = N_actual ≥ 0`. Если встреч меньше, чем `N`, стоимость равна числу встреч, а не `N`. Стоимость **возвращается** решением и **не списывается** с `energy`: спецификация говорит о когнитивных единицах, а не о ресурсе действий.

## Оценка одного эпизода

```text
w(x, p) = x * (1 + p * x)
```

| Ход оппонента | `p = −1` | `p = 0` | `p = +1` |
| --- | --- | --- | --- |
| C | −2 | −1 | 0 |
| D | 0 | +1 | +2 |

Отрицательный `p` усиливает сотрудничество и ослабляет дефекцию. Положительный — наоборот. `p = 0` симметричен.

## Временной вес

Для эпизода с номером `i` в окне длины `N` (`i = 1` — самый старый, `i = N` — самый новый):

```text
a_i = λ^(N - i)
```

Самый новый эпизод всегда имеет вес 1, в том числе при `λ = 0` (в коде возраст 0 не возводится в степень). При `λ = 0` все более старые веса равны 0. При `λ = 1` веса равны.

## Сумма и ход

```text
S = a_1*w_1 + … + a_N*w_N
```

Это сумма, не среднее. Знак `S` и знак среднего совпадают, но число `S` — именно сумма (пример: `C → C → D`, `λ = 1`, `p = 0` даёт `S = −1`).

| Условие | Ход |
| --- | --- |
| Нет эпизодов в окне и `p < 0` | C |
| Нет эпизодов в окне и `p > 0` | D |
| Нет эпизодов в окне и `p = 0` | C или D с вероятностью 1/2 |
| `S > 0` | D |
| `S < 0` | C |
| `S = 0` | C или D с вероятностью 1/2 |

Нулевая сумма при непустом окне — это ничья по истории, а не правило «первого хода». Пример: `p = −1` и единственная дефекция дают `S = 0` и случайный ход.

Сравнение с нулём — точное сравнение `float64`, как в прямой сумме. Монета: `rng.random() < 0.5` → C, иначе D.

## Память

`OpponentMemory` хранит действия оппонента по его id, от старого к новому. `last(opponent_id, 0)` возвращает пустое окно и счётчик чтений не увеличивает.

## Сериализация гена

`Genome` пишется и читается словарём `{shvgop, shpm, shz}`, JSON этой формы и байтами `AGN1` + int32 ШВГОП + два float64 (ШПМ, ШЗ). Поле агента — `genome: Genome | None`. Генерация популяции его не заполняет. HTTP-снимок агента гены не отдаёт: отдельного сохранения запущенного мира нет.
