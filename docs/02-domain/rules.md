# Правила и инварианты

## Жёсткие инварианты

1. **Занятость:** после применения движения тика в клетке не больше одного агента.
2. **Исключительность встречи:** агент состоит не более чем в одной активной встрече.
3. **Порядок радиусов:** `interaction_radius ≤ vision_radius`; оба `≥ 0`.
4. **Порядок матрицы PD:** `temptation > reward > punishment > sucker`.
5. **Детерминированная идентичность ячейки:** одинаковые `(seed, x, y)` → одинаковый hash.
6. **Потолок популяции:** count генерации в `[1, 100_000]` и не больше `map_width * map_height`.
7. **Границы карты:** клетки только в `[0, map_width) × [0, map_height)`; ход за край = stay.
8. **Еда:** ровно `food_capacity` единиц; не больше одной на клетку; не блокирует ход. Поиск врождённый. Поедание — отдельный `EatAction` (весь tick, без хода), только если Чебышёв ≤ `interaction_radius` уже на начало решения; подойти и съесть в одном tick нельзя. Доля `food_energy / n` → `agent.energy`; восполнение после удаления.

## Поведенческие правила

0. Пока `SimulationConfig.enable_pd=False` (сейчас по умолчанию), взаимодействия / встречи / раунды PD не стартуют; `InteractAction` в тике сводится к stay. Код PD не удалён.
1. World actions (move / interact / eat через стратегию) выбирают **свободные** агенты. Участник встречи не ходит и не interact, но может получить `EatAction`, если еда уже в радиусе.
2. Занятые агенты не могут быть инициаторами или целями новых взаимодействий.
3. Для контакта взаимное намерение не обязательно; достаточно одного валидного инициатора.
4. Взаимное намерение схлопывается в одно событие взаимодействия.
5. В конфликтах движения побеждает агент с наибольшим `move_priority(seed, tick, destination, agent_id)`; при равенстве hash — больший `agent_id`.
6. При конкуренции за interact фактически выигрывает более ранний/меньший id (см. механики).
7. Встреча кончается, если **хотя бы один** участник выбрал leave после раунда PD.
8. Отдельного score нет. **hp** — жизнь-таймер: random `[start_hp_min, start_hp_max]` при спавне; каждый тик −`hp_tick`; не пополняется. **energy** — ресурс действий (ход/stay/решения/раунд) и приток от еды/PD; старт `start_energy` (дефолт 100). Затраты не опускают hp/energy ниже 0.
9. Смерть — в конце тика при `hp ≤ 0` или `energy ≤ 0`: удаление агента и завершение встречи.
10. Новая встреча открывается только при `0 < Чебышёв ≤ interaction_radius` по клеткам на начало тика. По умолчанию радиус 1: восемь соседей, включая диагональ. Уже начатая встреча на следующих тиках соседства не требует; участники во встрече не ходят.
11. Reset обнуляет тик, агентов, еду, встречи и last step result; опционально меняет seed. Сохранённые конфиги мира reset не удаляет.
12. **Генетические шкалы** (если геном задан) оценивают только действия оппонента: окно ШВГОП, веса ШЗ, интерпретация ШПМ, решение по знаку суммы. Пустое окно решается знаком ШПМ. Когнитивная стоимость неотрицательна и в v0.1 не списывается с energy. Тик гены не меняет. Мутации и наследование в этой версии не определены. Подробности — в [genetics](genetics.md).

## Причинно-следственные связи

```text
радиусы восприятия
    → видимые агенты / еда
        → EatAction | Move к еде | Interact
            → события взаимодействия (если enable_pd)
                → встречи → раунды PD → изменение hp
    → движение / stay
        → траты hp
    → eat_intents → energy + восполнение еды
```

Движение параллельно открытию контакта, но по намерениям, выбранным до разрешения контакта; сам контакт опирается на позиции до хода. Поедание применяется после движения.

## Явные не-правила (не действуют / отсутствуют)

* Genome не влияет на решения.
* Biome не влияет на движение, зрение или выплаты.
* hp не запускает размножение и не растёт от PD/еды.
* Нехватка energy не блокирует действие в тике (стоимость упирается в 0), но `energy ≤ 0` в конце тика убивает.
