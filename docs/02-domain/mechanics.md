# Механики

## Пайплайн тика

Для каждого тика при непустой популяции:

1. **Снимок** продолжающихся активных встреч и клеток на начало тика.
2. **Решение** — каждый **свободный** агент наблюдает и выбирает world action. Участник встречи не ходит и не interact; если рядом есть еда в `interaction_radius`, пайплайн назначает `EatAction`.
3. **Разрешение взаимодействий** (только если `enable_pd=True`) по interact-намерениям и по позициям на начало тика. При `enable_pd=False` `InteractAction` сводится к stay.
4. **Открытие встреч** из разрешённых контактов (оба ещё должны быть свободны). Дистанцию повторно не проверяют.
5. **Разрешение движения** по move-намерениям (`EatAction` → stay; инициаторы interact по умолчанию stay; участники встречи без eat — stay). Ход за край карты = stay.
6. **Траты energy за мир:** успешный переход — `energy_move` (2); остался в клетке — `energy_stay` (1). `InteractAction` дополнительно — `energy_play_decision` (1). Ниже 0 не опускается.
7. **Поедание еды** по `eat_intents`: валидные едоки делят `food_energy` → `energy`; восполнение.
8. **Раунды PD** (если `enable_pd=True`): приток матрицы → **energy**, затем `energy_game`, затем `energy_play_decision` за continue/leave.
9. **Трата жизни:** у каждого живого агента −`hp_tick` (дефолт 1). Жизнь не пополняется.
10. **Смерть:** `hp ≤ 0` или `energy ≤ 0` → удаление и завершение встречи.
11. Увеличение счётчика тика мира (`PythonEngine` после `step_tick`).

Пустая популяция: тик всё равно растёт; решений и встреч нет.

## Восприятие

* Метрика: **Чебышёв** — `max(|dx|, |dy|)`. Это 8 соседей при радиусе 1, не 4-соседство.
* По умолчанию `vision_radius = 3`, `interaction_radius = 1`.
* Зрение: другие агенты и еда с расстоянием `≤ vision_radius` (включительно).
* Старт interact: `0 < distance ≤ interaction_radius`.
* Поедание: Чебышёв ≤ `interaction_radius` уже на момент решения (и снова проверяется после хода).
* Себя агент не видит.

## Движение

* Все move-намерения тика собираются и применяются атомарно.
* Кардинальные ходы сдвигают ячейку на один шаг; stay оставляет ячейку.
* После успешного хода агент центрируется в новой ячейке.
* Цель вне `[0, W) × [0, H)` трактуется как stay.

### Правила конфликтов (кратко)

* Несколько агентов в одну пустую клетку: побеждает наибольший `move_priority(seed, tick, dest, agent_id)` (детерминированная жеребьёвка); при равенстве hash — больший `agent_id`.
* Ход в клетку, чей жилец остаётся: ход проваливается.
* Цепочка ходов в освобождаемые клетки: успех, если успешна вся цепочка ухода.
* Циклическая зависимость между ходящими: провал (остаются на месте).

Точная процедура — в [algorithms](algorithms.md).

## Еда

* Начальный спавн: `food_capacity` случайных свободных клеток внутри карты.
* Поиск: ближайшая видимая еда по Манхэттену; шаг к ней одним кардинальным направлением.
* `EatAction` занимает весь тик (без хода). Подойти и съесть в одном тике нельзя.
* Несколько `EatAction` на одну порцию: доля `food_energy / n` каждому.
* После удаления — восполнение на клетку с наименьшей локальной плотностью (агенты + еда в `food_density_radius`); ничья — через `move_priority`.

## Разрешение взаимодействий

Даны намерения initiator → target за тик (активно при `enable_pd=True`):

1. Отбросить самонаведение, вне радиуса и с участием занятых (уже во встрече) агентов.
2. Предпочесть **взаимные** контакты (оба направления есть): одно событие на неупорядоченную пару; оба — initiators.
3. Затем оформить **односторонние** контакты по оставшимся валидным намерениям.
4. Агент участвует не более чем в одном контакте за тик (первое «захват» в порядке разрешения).
5. При нескольких инициаторах на одну цель побеждает обработка с меньшим id / множество `used` (**Fact** из тестов: меньший id инициатора выигрывает конкуренцию за цель).

Контакты используют **позиции на начало тика**. Цель, выбравшая движение, всё равно может уехать после фиксации контакта; участники встречи в том же тике могут оказаться в разных клетках (**Fact** из тестов).

## Встречи

* Контакт создаёт встречу, если оба свободны и ещё не привязаны к встрече.
* Оба становятся `IN_MEETING` и делят meeting id.
* В тике создания сразу играется первый раунд PD (после разрешения движения и еды).
* На следующих тиках активные встречи играют ещё раунд без world-решений участников (ход запрещён; eat разрешён).
* Продолжение **не** проверяет дистанцию.
* После каждого раунда, в таком порядке:
  * к **energy** прибавляется выплата раунда;
  * списывается стоимость раунда (`energy_game`);
  * списывается стоимость выбора continue/leave (`energy_play_decision`);
  * если оба continue → номер раунда +1, встреча активна;
  * иначе → встреча завершена, агенты свободны.
* В конце тика у всех −`hp_tick` жизни; при `hp ≤ 0` или `energy ≤ 0` агент удаляется.

## Временная политика решений

Поставляемая политика по умолчанию — **временная случайная тестовая стратегия** (явно не часть механики мира):

* если есть еда в `interaction_radius` → `EatAction`;
* иначе если видна еда → ход к ближайшей;
* иначе при `enable_pd=True` с некоторой вероятностью — interact со случайным доступным соседом;
* иначе — случайный кардинальный ход / stay;
* на встрече — случайные cooperate/defect и continue/leave.

Ожидается замена на реальные эволюционные или скриптовые стратегии.
