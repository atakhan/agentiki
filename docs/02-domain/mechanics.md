# Механики

## Пайплайн тика

Для каждого тика при непустой популяции:

1. **Снимок** продолжающихся активных встреч.
2. **Решение** — каждый **свободный** агент наблюдает и выбирает world action; уже во встрече — пропускают решение (стоят).
3. **Разрешение взаимодействий** по interact-намерениям (занятые агенты исключены).
4. **Открытие встреч** из разрешённых контактов (оба ещё должны быть свободны).
5. **Разрешение движения** по move-намерениям всех агентов (инициаторы interact по умолчанию stay; участники встречи без решения — stay).
6. **Раунды PD** для продолжающихся встреч, затем для только что начатых.
7. Увеличение счётчика тика мира.

Пустая популяция: тик всё равно растёт; решений и встреч нет.

## Восприятие

* Метрика: **Чебышёв** — `max(|dx|, |dy|)`.
* Зрение: другие агенты с расстоянием `≤ vision_radius` (включительно).
* Доступны для interact: `0 < distance ≤ interaction_radius`.
* Себя агент не видит.

## Движение

* Все move-намерения тика собираются и применяются атомарно.
* Кардинальные ходы сдвигают ячейку на один шаг; stay оставляет ячейку.
* После успешного хода агент центрируется в новой ячейке.

### Правила конфликтов (кратко)

* Несколько агентов в одну пустую клетку: побеждает **наименьший agent id**; остальные остаются.
* Ход в клетку, чей жилец остаётся: ход проваливается.
* Цепочка ходов в освобождаемые клетки: успех, если успешна вся цепочка ухода.
* Циклическая зависимость между ходящими: провал (остаются на месте).

Точная процедура — в [algorithms](algorithms.md).

## Разрешение взаимодействий

Даны намерения initiator → target за тик:

1. Отбросить самонаведение, вне радиуса и с участием занятых (уже во встрече) агентов.
2. Предпочесть **взаимные** контакты (оба направления есть): одно событие на неупорядоченную пару; оба — initiators.
3. Затем оформить **односторонние** контакты по оставшимся валидным намерениям.
4. Агент участвует не более чем в одном контакте за тик (первое «захват» в порядке разрешения).
5. При нескольких инициаторах на одну цель побеждает обработка с меньшим id / множество `used` (**Fact** из тестов: меньший id инициатора выигрывает конкуренцию за цель).

Контакты используют **позиции на начало тика**. Цель, выбравшая движение, всё равно может уехать после фиксации контакта; участники встречи в том же тике могут оказаться в разных клетках (**Fact** из тестов).

## Встречи

* Контакт создаёт встречу, если оба свободны и ещё не привязаны к встрече.
* Оба становятся `IN_MEETING` и делят meeting id.
* В тике создания сразу играется первый раунд PD (после разрешения движения).
* На следующих тиках активные встречи играют ещё раунд без world-решений участников.
* После каждого раунда:
  * score растёт на выплаты;
  * если оба continue → номер раунда +1, встреча активна;
  * иначе → встреча завершена, агенты свободны.

## Временная политика решений

Поставляемая политика по умолчанию — **временная случайная тестовая стратегия** (явно не часть механики мира):

* с некоторой вероятностью — interact со случайным доступным соседом;
* иначе — случайный кардинальный ход / stay;
* на встрече — случайные cooperate/defect и continue/leave.

Ожидается замена на реальные эволюционные или скриптовые стратегии.
