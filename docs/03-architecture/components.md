# Компоненты

## SimulationEngine (protocol)

* **Назначение:** стабильный контракт бэкендов.
* **Входы:** seed, число шагов, параметры генерации, запросы observation.
* **Выходы:** ячейки, агенты, результаты step (взаимодействия, встречи, раунды PD).
* **Зависимости:** ничего «сверху»; реализуется `PythonEngine` (и будущим Rust).

## PythonEngine

* **Назначение:** in-process Python-бэкенд.
* **Владеет:** seed/tick мира, `BoundedWorld`, `AgentPopulation`, `FoodStore`, `MeetingStore`, экземпляром стратегии, последним `StepResult`.
* **Сотрудничает с:** модулями пайплайна `step_tick`.
* **Замечание:** отдаёт `spatial` / `spatial_cell_size`, но запросы восприятия идут через spatial-индекс популяции (см. `REVIEW.md`).

## BoundedWorld

* **Назначение:** ячейки по запросу внутри `[0, W) × [0, H)`, детерминированно по seed.
* **Вход:** координаты + seed + размеры карты.
* **Выход:** записи `Cell`; вне bounds — ошибка / клип в `iter_cells`.

## AgentPopulation

* **Назначение:** хранение агентов, карта занятости, spatial-индекс, генерация, атомарное применение позиций.
* **Инварианты:** уникальность занятости.

## Пайплайн тика (`step_tick`)

* **Назначение:** оркестрация одного тика: observe → decide → interact/meet (если `enable_pd`) → move → eat → PD → death.
* **Зависит от:** протокола стратегии, популяции, food store, config, meeting store, RNG.

## Подсистема движения

* **Назначение:** построение intents и разрешение одновременных ходов.
* **Ключевое правило:** победитель цели — max `move_priority(seed, tick, dest, id)` (жеребьёвка) + логика цепочек/зависимостей; цель вне карты = stay.

## Подсистема еды

* **Назначение:** спавн / perception / `EatAction` / shared consumption / density replenishment.
* **Модули:** `food.py`, `foraging.py`.

## Подсистема взаимодействий

* **Назначение:** превратить interact-намерения в события контакта (при `enable_pd=True`).

## Подсистема встреч + PD

* **Назначение:** жизненный цикл встречи, выплаты в energy, continue/leave (при `enable_pd=True`).

## Генетические шкалы

* **Назначение:** по геному и истории действий оппонента выбрать cooperate/defect и сообщить когнитивную стоимость.
* **Модуль:** `genetics.py`. В пайплайн тика и в стратегию по умолчанию не входит.

## Подсистема восприятия

* **Назначение:** строить observation (агенты + еда); классифицировать interactable-смещения.

## Стратегия

* **Назначение:** observation (+ контекст встречи) → Eat / Move / Interact / PD / continue.
* **Сейчас:** только временная `RandomTestStrategy` (eat → seek food → random move; interact только если PD включён).

## Приложение FastAPI

* **Назначение:** HTTP API + опциональный mount статики UI + CORS для origin Vite.
* **Lifecycle:** создаёт движок из env при старте.

## React-приложение

| Часть | Роль |
| --- | --- |
| `App` | Экраны home / load / config / sim, play loop, выделение, оверлеи |
| `HomeScreen` | «Новый мир» и «Загрузить мир» |
| `LoadScreen` | Список сохранённых имён; выбор открывает экран конфига |
| `ConfigScreen` | Размер карты, число агентов, плотность 1–10, правила еды и жизни, «Старт», «Сохранить конфиги» |
| `TopBar` | На симуляции: play/pause, «Рестарт», zoom ±, «Вид» (масштаб и px ячейки), «←» на главную. Нет count, плотности, «Жизнь», «Шаг» и «×10» |
| `WorldCanvas` | Камера по указателю, цикл отрисовки (агенты + еда) |
| инспектор | Тост по выбранному агенту: hp, energy, состояние встречи, tick, радиусы. Отдельного поля score нет |
| `api.ts` | Обёртки fetch, включая конфиги мира |
| `world/*` | Хеш, рендереры сетки/агентов/зрения/взаимодействий, анимация |

## Контракты данных (модели API)

Pydantic-модели зеркалят доменные понятия в JSON (`WorldOut`, `AgentOut`, `StepOut`, observation, раунд PD и т.д.). TypeScript-типы фронта параллельны этим формам.
