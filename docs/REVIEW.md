## Неясное / незавершённое намерение

* Полный эволюционный цикл (отбор по score + genome) не реализован; `genome` — мёртвое поле.
* Желательно ли долгосрочно, чтобы цель встречи в том же тике могла уехать — **Unknown**; тесты закрепляют текущее поведение.
* `Observation.for_strategy()` скрывает id, а единственная стратегия id использует — форма API стратегии недоделана.
* `PythonEngine.spatial` / `spatial_cell_size=4.0` vs `AgentPopulation.spatial` с `cell_size=1.0`: индекс движка, похоже, не используется (мёртвое состояние). Зачем отдавать `spatial_cell_size` в API — неясно (кроме будущего использования).

## Мёртвый или stub-код

* `Agent.genome`
* `PythonEngine.spatial` (только clear)
* `cell_biome` / `cell_color` игнорируют входы (хеш всё равно считается)
* Загрузчик Rust-бэкенда (ожидается внешний модуль)

## Отсутствующие тесты

* Слой HTTP/API
* Фронтенд
* Паритет хеша Python ↔ TypeScript
* Интеграционный тест режима ошибки `create_engine(..., backend="rust")` (опционально)
* Производительность на больших популяциях

## Архитектурные риски

* In-memory singleton-движок: небезопасен для multi-worker без sticky sessions / внешнего состояния.
* Неаутентифицированные разрушительные контролы (`reset`, `generate`, `step`) при публичном доступе к порту.
* Стратегия зашита в `PythonEngine` — неудобно A/B-тестировать без правки кода.
* Порядок стадий тика тонкий; смена может незаметно сломать связку meeting/move.

## Маркеры TODO в коде

* Комментариев `TODO`/`FIXME` не найдено.
* Явные пометки «temporary» / «rust later» в strategy и engine.

## Где намерение автора восстановить нельзя

* Почему min agent id (а не random / priority / energy) в конфликтах.
* Почему continue на встрече — двустороннее вето, а не другая длина встречи.
* Почему генерация очищает всю популяцию, а не дополняет.
* Целевой дизайн визуала/биомов сверх stub-серого.
