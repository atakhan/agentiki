# Обзор проекта (на момент документации)

Находки по чтению кодовой базы. Источник истины по поведению — **код**; этот файл фиксирует известные пробелы и расхождения.

Сверка доков с кодом (карта W×H, еда/`EatAction`, жеребьёвка движения, `enable_pd`): 2026-11-22.

## Документация vs код (история)

| Тема | Более ранние заметки | Код сейчас |
| --- | --- | --- |
| Границы мира | «бесконечная сетка» | `BoundedWorld` `[0, W)×[0, H)`, жёсткий край |
| Конфликт движения | «меньший agent id» | max `move_priority` (hash-лотерея); tie → больший id |
| Действия | только move / interact | + `EatAction`; стратегия: eat → seek food → move |
| Валюта | score / траты с hp | hp = таймер жизни; energy = действия + еда + PD; score нет |
| PD | всегда в пайплайне | `enable_pd=False` по умолчанию; код сохранён |
| Спавн | диск к центру | квадратная решётка + `food_capacity` порций |

**Правило:** для фактического поведения источник истины — код.

## Неясное / незавершённое намерение

* Полный эволюционный цикл (отбор, размножение, мутации, стартовые гены) не реализован. Ядро трёх шкал есть (`genetics.py`) и тиком не вызывается; когнитивная стоимость в `energy` не переводится.
* Контакт (при включённом PD) решается по клеткам начала тика. Цель может уйти в том же тике; встреча после этого продолжается без проверки дистанции.
* `Observation.for_strategy()` скрывает id, а стратегия id использует — форма API стратегии недоделана.
* `PythonEngine.spatial` / `spatial_cell_size=4.0` vs `AgentPopulation.spatial` с `cell_size=1.0`: индекс движка, похоже, не используется.

## Мёртвый или stub-код

* `Agent.genome` пуст после генерации и не читается тиком (тип уже `Genome`, не bytes)
* `PythonEngine.spatial` (только clear)
* `cell_biome` / `cell_color` игнорируют входы (хеш всё равно считается)
* Загрузчик Rust-бэкенда (ожидается внешний модуль)
* PD/meetings при `enable_pd=False` не выполняются, но модули остаются

## Отсутствующие тесты

* Слой HTTP/API
* Фронтенд
* Паритет хеша Python ↔ TypeScript
* Интеграционный тест режима ошибки `create_engine(..., backend="rust")` (опционально)
* Производительность на больших популяциях

## Архитектурные риски

* In-memory singleton-движок: небезопасен для multi-worker без sticky sessions / внешнего состояния.
* Неаутентифицированные разрушительные контролы (`reset`, `generate`, `step`) при публичном доступе к порту.
* Стратегия зашита в `PythonEngine` — неудобно A/B-тестировать без правки кода.
* Порядок стадий тика тонкий; смена может незаметно сломать связку meeting/move/food.

## Где намерение автора восстановить нельзя

* Достаточно ли hash-жеребьёвки конфликтов, или нужен bias по энергии/стратегии.
* Когда и как `energy` начнёт влиять на жизнь/решения.
* Почему continue на встрече — двустороннее вето, а не другая длина встречи.
* Почему генерация очищает всю популяцию, а не дополняет.
* Целевой дизайн визуала/биомов сверх stub-серого.
