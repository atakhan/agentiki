# Решение: Стабильный протокол SimulationEngine со сменяемыми бэкендами

## Контекст

Симуляции позже может понадобиться более быстрое ядро без переписывания control plane и UI.

## Альтернативы

* По доступным материалам неизвестны (другие варианты в репозитории не описаны).

## Решение

Отдавать наружу только `SimulationEngine`; FastAPI использует его; `create_engine(backend=...)` — Python сейчас, Rust/pyo3 позже (`agentiki_sim_rust`).

## Причина

Сформулировано в `protocol.py` и README: контракт стабилен, чтобы Rust мог заменить `PythonEngine`.

## Последствия

* API и UI не зависят от бэкенда.
* Rust должен совпадать с поведением протокола, включая ожидания детерминизма.
* Пока модуля нет, `backend=rust` падает в runtime.

# Решение: Фиксированная карта W×H; seed-hash клеток; камера на клиенте

## Контекст

Нужна обозримая карта с предсказуемыми границами без хранения тайловой БД.

## Альтернативы

* Бесконечное поле (раньше).
* Тороид (wrap) — отложен.

## Решение

Прямоугольник `[0, width) × [0, height)` задаётся при создании мира. Ячейки внутри по-прежнему из `(seed, x, y)` (общий u32-хеш Python/TS). Край жёсткий. Камера в браузере; сервер отдаёт `map_width` / `map_height` и агентов.

## Причина

Фиксированный размер нужен для контролируемых экспериментов и размещения популяции; hash оставляет поле детерминированным без хранения сетки.

## Последствия

* Алгоритмы хеша клиента и сервера должны совпадать.
* Генерация и движение обязаны уважать bounds.
* Нет серверного состояния камеры/viewport.
* Biome/color могут оставаться заглушками.

# Решение: Одновременный тик с явными правилами конфликтов

## Контекст

Многоагентному движению по сетке нужно однозначное одновременное обновление.

## Альтернативы

* Неизвестны (пошаговый ход, непрерывная физика и т.п. в репозитории не обсуждаются).

## Решение

Все свободные агенты решают, затем в одном тике разрешаются взаимодействия, встречи и ходы; конфликты за цель — детерминированная жеребьёвка `priority = hash(seed, tick, destination, agent_id)` (побеждает max); цепочки занятости — рекурсивно.

## Причина

Нужна воспроизводимость без постоянного преимущества меньших id и без отдельного состояния справедливости.

## Последствия

* Шансы претендентов уравнены относительно seed; победитель не привязан к порядку обхода.
* Поведение тестируемо и воспроизводимо по seed при фиксированной стратегии.
* Rust-бэкенд должен реализовать тот же `move_priority` (u32 mix).

# Решение: Жизнь-таймер и energy как ресурс действий

## Контекст

Раньше траты хода/PD списывались с hp, а еда копила отдельный energy — экономика была перепутана.

## Решение

* **hp** — только срок жизни: random `[start_hp_min, start_hp_max]` при спавне, каждый тик −`hp_tick`, без пополнения.
* **energy** — действия (бывшие hp-траты) и приток (еда + PD payoffs); старт `start_energy` (дефолт 100) в конфиге мира; `energy ≤ 0` → смерть.

## Последствия

* PD больше не лечит жизнь; выплаты идут в energy.
* Без еды/удачных PD агент рано или поздно умирает от энергии, даже если hp ещё есть.

# Решение: Еда и отдельный EatAction

## Контекст

Нужен ресурс на карте и врождённый поиск без genome/PD.

## Альтернативы

* Автопоедание при контакте в том же тике после хода.
* Отдельный шаг поедания после подхода.

## Решение

`food_capacity` порций на карте; seek по Манхэттену; поедание только через `EatAction` на отдельном тике, когда еда уже в `interaction_radius`. Доля `food_energy / n` → `agent.energy`. Восполнение по плотности.

## Причина

Подход и поедание — разные действия: нельзя «дойти и съесть» за один тик.

## Последствия

* `energy` отделён от hp; еда и PD его пополняют, действия тратят.
* Стратегия по умолчанию: eat → seek → random move.
* Участник встречи может есть, но не ходит.

# Решение: Взаимодействия открывают встречи с Prisoner's Dilemma

> Сейчас выключено по умолчанию (`enable_pd=False`). Код и тесты с `enable_pd=True` сохранены.

## Контекст

Пространственным агентам нужна модель взаимодействия с выплатами в жизнь (hp).

## Альтернативы

* Неизвестны.

## Решение

Разрешённые контакты создают парные встречи; каждый тик активной встречи — раунд PD с continue/leave; hp меняется выплатами из матрицы.

## Причина

Причина решения не установлена по доступным материалам (доменный выбор виден в коде/тестах, без прозаического обоснования).

## Последствия

* Отбора пока нет. Отдельного score нет: PD-выплаты и траты действий идут в `energy`; hp только тикает вниз.
* Новая встреча только у соседей на начало тика. В тике открытия цель может уйти; на следующих тиках встреча соседство не перепроверяет, участники стоят.

# Решение: Генетическое ядро v0.1 не входит в тик

## Контекст

Спецификация шкал задаёт оценку оппонента (ШВГОП, ШПМ, ШЗ), когнитивную стоимость и требование держать гены в диапазонах. Вероятности мутаций, шаг мутации, наследование от двух родителей и стартовое распределение она явно откладывает.

## Альтернативы

* Сразу заменить `choose_pd` у `RandomTestStrategy` и списывать стоимость с `energy`.
* Выдумать шаги мутации и смешивание родителей, чтобы ген «заработал» в популяции.

## Решение

Реализовать чистый модуль `sim/genetics.py`: геном, память эпизодов, сумма по окну, ход, неотрицательная стоимость, сериализация. `N_max` ШВГОП принять равным 256. Тик, спавн и стратегию по умолчанию не трогать. Стоимость не вычитать из `energy`. Операторы мутации и наследования не добавлять.

## Причина

Встречный ход PD сейчас выбирает подключаемая стратегия; подмена её генетикой изменила бы наблюдаемое поведение без правил размножения. Когнитивная единица в спецификации не отождествлена с `energy`. Числа мутаций в спецификации нет, поэтому подставлять их нельзя.

## Последствия

* Прогнать эволюцию на трёх генах пока нельзя: некому записать эпизод, некому родить потомка и некому задать начальный геном.
* Следующий шаг — отдельно решить память встреч, списание КЕ и операторы наследования, затем подключить `decide_against` к выбору PD.
